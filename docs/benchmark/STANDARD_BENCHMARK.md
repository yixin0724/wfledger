# Standard Benchmark

The standard benchmark is a fixed comparison matrix of the maintained algorithm corpus. Every run
writes a manifest-v4 evidence bundle that a third party can audit with the Python auditor, without
Java. The driver is
[BenchmarkExecutor](<../../experiments/src/main/java/org/workflowsim/experiments/benchmark/BenchmarkExecutor.java>).

## Matrix

| Axis | Values |
|---|---|
| Inputs | Epigenomics 100 and 997, CyberShake 100 and 1000, Inspiral 100 (`datasets/dax`) |
| VM tiers | 8 VMs (fat-tree k=4, 16 Hosts) and 32 VMs (fat-tree k=8, 128 Hosts); 1000 MIPS, 1 PE, SPACE_SHARED |
| SHARED_DAG layer | `SHARED_STORAGE_HEFT`, `_CPOP`, `_DLS`, `_ETF`, `_PEFT`; SHARED file system, `LEGACY_WORKFLOWSIM_V1` |
| LOCAL_DAG layer | `LOCAL_HEFT`, `LOCAL_CPOP`, `LOCAL_PEFT` on two networks: `PRE_EXECUTION_TRANSFER_DELAY_WITH_CONTENTION_V1` (endpoint) and `PRE_EXECUTION_TRANSFER_DELAY_WITH_FAT_TREE_CONTENTION_V1` (fat-tree constrained) |
| ONLINE layer | `FCFS`, `READY_BATCH_MINMIN`, `READY_BATCH_MAXMIN`, `READY_BATCH_MCT`, `READY_BATCH_ROUNDROBIN`; `LEGACY_WORKFLOWSIM_V1` |
| Seed | 11, one run per condition (the algorithms are deterministic) |

This gives 5 × 2 × (5 + 3 × 2 + 5) = 160 grid cells. Comparisons are made within one decision
layer only. At 32 VMs the LOCAL layer uses a k=8 fat-tree, so VM count and topology change
together.

## Variants

| Protocol | Platform declaration | Cells | Index |
|---|---|---:|---|
| `benchmark-standard-carbon-v1` (default) | Linear power per VM (idle 250 W, max 400 W) and uniform intensity 380 gCO₂/kWh on the 160 grid cells, plus 10 budget-model cells (`SHARED_STORAGE_HEFT` per input × tier) declaring only the windows `[0, 3600) @ 300 W` and `[3600, 7200) @ 600 W` | 170 | `benchmark-carbon.json` |
| `benchmark-standard-dvfs-v1` | A five-tier P-state table on every VM plus intensity 380 gCO₂/kWh; policies `DEFAULT`, `MIN_POWER`, `EDP_HEURISTIC` on one representative algorithm per layer (`SHARED_STORAGE_HEFT`, `LOCAL_HEFT` on the endpoint network, `FCFS`) | 90 | `benchmark-dvfs.json` |

Intensity and budget windows are mutually exclusive on one platform; `carbonMetrics` is present
exactly when a carbon model is declared. The DVFS tier table (first tier is the default):

| Tier | mips | idlePowerWatts | maxPowerWatts |
|---|---:|---:|---:|
| turbo (default) | 2000 | 250 | 4000 |
| nominal | 1000 | 250 | 400 |
| half | 500 | 100 | 118.75 |
| quarter | 250 | 50 | 52.34375 |
| eighth | 125 | 25 | 25.29296875 |

Dynamic power of the lower tiers follows `150 × (mips/1000)³` W on top of idle 0.2 W/MIPS. Idle
power is always charged at the default tier, so a deep tier can lose energy when the longer
makespan's idle exposure outweighs its busy savings; the direction depends on utilization.

The archives `benchmark-standard-v1` (no power model) and `benchmark-standard-power-v1` (power
only) were produced by earlier revisions of the driver; they are audited as frozen evidence and
are not regenerated by the current executor.

## Running

From the repository root, into a new output directory:

```bash
mvn -q -pl :workflowsim-workbench -am compile exec:java \
  -Dexec.mainClass=org.workflowsim.experiments.benchmark.BenchmarkExecutor \
  -Dexec.args="$PWD/datasets $PWD/output/<new-benchmark-directory>"

# DVFS variant
mvn -q -pl :workflowsim-workbench -am compile exec:java \
  -Dexec.mainClass=org.workflowsim.experiments.benchmark.BenchmarkExecutor \
  -Dexec.args="dvfs $PWD/datasets $PWD/output/<new-dvfs-directory>"
```

The executor refuses an existing output directory.

## Auditing

Retained evidence lives only in `output/*-evidence.tar.gz` archives. Restore an archive into a
**new, empty** directory and write the audit report to another new path; never modify restored
evidence in place:

```bash
RESTORE=/absolute/new-empty-restore-directory
mkdir -p "$RESTORE"
tar -xzf output/benchmark-standard-v1-evidence.tar.gz -C "$RESTORE"
PYTHONDONTWRITEBYTECODE=1 python3 scripts/verify-study-evidence.py \
  --output /new-path/benchmark-audit.json \
  "$RESTORE"/benchmark-standard-v1/runs/*/result.manifest.json
```

The same pattern applies to `benchmark-standard-power-v1`, `benchmark-standard-carbon-v1`, and
`benchmark-standard-dvfs-v1`, and to freshly generated output. The auditor recomputes, from each
manifest's own fields:

- energy: `E = Σ_vm P_idle × T_sim + (P_max − P_idle) × T_busy`;
- tiered energy: default-tier idle over `T_sim` plus each tier's dynamic power over its busy time,
  with the per-tier ledger rebuilt from per-Job `tierMips` and tier-speed task windows;
- intensity carbon: `Σ_vm E_vm[J] / 3.6e6 × I_vm[g/kWh]`;
- budget carbon: the fleet-power excess over each window's green budget, from the compute-Job
  intervals.

## Energy portrait analysis

[analyze-energy-portrait.py](<../../scripts/analyze-energy-portrait.py>) analyzes a run directory
of the power-only matrix (for example a restored `benchmark-standard-power-v1`):

```bash
PYTHONDONTWRITEBYTECODE=1 python3 scripts/analyze-energy-portrait.py \
  "$RESTORE"/benchmark-standard-power-v1 /new-path/portrait.json
PYTHONDONTWRITEBYTECODE=1 python3 scripts/test-energy-portrait.py
```

- Comparisons are within one layer against the family reference (`SHARED_STORAGE_HEFT`,
  `LOCAL_HEFT`, `FCFS`); each (input, VM tier) cell is one paired condition.
- The test is a paired two-sided exact sign test on non-tied conditions; ties are reported, not
  discarded silently. Holm correction applies within each layer (m = 4).
- Rankings use the root-mean-square EDP over the layer's conditions.
- For each policy pair within a condition, the analyzer decomposes the energy difference into the
  idle term `P_idle × ΔT` and the busy-drift term `ΔP × Δbusy`, and reports their ratio where the
  busy term dominates. Busy intervals are not workload-fixed across policies.
- The output schema is `workflowsim-energy-portrait-v1`. Without retained evidence the analyzer
  reports that no run manifests were found, and the self-test skips its retained-data case.
- `READY_BATCH_MCT` and `FCFS` produce identical assignment streams on a uniform-VM fleet, so their
  comparison is all ties by construction.

## Boundaries

- Results describe the declared simulation models on these platform profiles, not production
  clusters. Joules and grams are declared-model values.
- The three layers belong to different decision phases and model families and are not ranked
  against each other.
- One seed per deterministic condition gives repeats, not independent samples; no multi-seed
  inference is made.
- The platform is a single fleet with uniform intensity; spatial (cross-region) shifting is not
  modeled, and fleet power after the last budget window contributes no excess.
- DVFS assignment is one tier per Job at dispatch; `MIN_POWER` and `EDP_HEURISTIC` are frequency
  policies, not schedulers.
